# Choose a database workflow

Evaluate a database client by completing a task you already know. Use the same development source and database account so differences in permissions or data do not distort the comparison.

## Pick a representative task

Choose something with a result you can verify: find an order, inspect its related records, run a report, or load a fixture. Include the source types and deployment surface you actually need.

| Question | What to test in WhoDB |
| --- | --- |
| Can I reach my source? | Connect with the required endpoint and TLS settings |
| Can I find the relevant records? | Inspect **Info**, open **Data**, and apply a source filter |
| Can I understand the relationships? | Select the relevant objects in **Graph** and inspect their keys |
| Can I investigate a query? | Keep sample, join, and aggregate cells in **Scratchpad** |
| Can I move the required data? | Export a query result or preview a representative import |
| Can I use my model? | Configure the provider, ask a small question, and inspect the generated SQL |
| Can I repeat the check? | Use the CLI and inspect its structured output |

## Check the operational fit

Test the exact build and database you plan to use. Check file access from the server's location, connection reachability, and account permissions. Browser, desktop, and terminal workflows can have different network and file paths.

Keep durable queries, migrations, and fixtures outside the client. This lets you compare tools without making the evaluation itself the only copy of useful work.

## Compare against current documentation

Use the other product's official documentation for its current features, editions, and packaging. Avoid relying on a static list of competitor limitations.

Start with [Quick start](/quick-start), then use the guide for [DBeaver](/resources/comparisons/vs-dbeaver), [pgAdmin](/resources/comparisons/vs-pgadmin), [phpMyAdmin](/resources/comparisons/vs-phpmyadmin), or [TablePlus](/resources/comparisons/vs-tableplus).
