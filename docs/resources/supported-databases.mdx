# Supported Databases

Use this catalog to choose the source type for your connection and check its main workflows. CE connects to SQL databases, local database files, document stores, caches, and search systems.

Choose the entry matching the actual product when one is available. Compatible entries share a connector family, but differences in the server can still affect syntax, metadata, and supported operations. Test the queries and changes you need against your own source version.

## Understand the differences

### Managed cloud variants

`DocumentDB` and `ElastiCache` are marked as AWS-managed catalog entries. They can be introduced through configured profiles or opt-in CLI discovery; they are not ordinary choices in the web credential form.

### Local database files

`SQLite3` and `DuckDB` use a database file path instead of host and port fields. The file must be accessible to the WhoDB process. In Docker, mount its directory and enter the container path. The desktop app offers a native file picker.

### Available operations

Not every database type exposes the same feature set:

- SQL-capable databases generally support Scratchpad, graph/schema views, and mock data generation
- MongoDB-family and Redis-family systems support Scratchpad using their native command syntax rather than SQL
- Memcached and search systems use narrower capability sets
- Database switching and schema support vary by family

### Build availability

DuckDB availability depends on the build target. Check that it appears in the connection form for the artifact you installed before planning a file-based workflow around it.

## Connection profiles

Profiles use `WHODB_<TYPE>` JSON arrays or numbered variables such as `WHODB_POSTGRES_1`. The type name is uppercased. Cloud-managed entries also accept this profile pattern; local CLI discovery is another way to find their endpoints.

See [Installation](/installation#database-connection-profiles) for examples and shared-profile access implications.
