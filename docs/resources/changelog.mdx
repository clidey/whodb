# Follow releases

Use [WhoDB releases](https://github.com/clidey/whodb/releases) to find published versions, release notes, and downloadable artifacts. Check the notes for the version you plan to install, including any configuration or compatibility changes relevant to your deployment.

## Prepare an update

Record your current image tag or binary version and retain the deployment configuration. Use a specific published tag when you need a deployment that can be reproduced rather than following `latest` automatically.

Keep the WhoDB data directory and encryption key if existing login sessions must survive replacement. Keep database backups independently: updating the database client and protecting the connected database are separate tasks.

## Verify the updated instance

Open a fresh browser session and connect to a development source. Inspect a known object's fields and run a small read query. Test the operations your team uses, such as importing a fixture, exporting a query result, or reaching a configured model endpoint.

If behavior differs from these docs, record the installed version and source type before reporting it. The documentation follows current CE source behavior; the catalog and available actions can vary by version and build target.

[Installation](/installation) explains the deployment options. [Report an issue](https://github.com/clidey/whodb/issues) with a minimal reproduction if an update breaks a workflow.
