# Use WhoDB with MySQL and MariaDB

Use WhoDB's MySQL or MariaDB connection type to browse a database, inspect records, and run the SQL accepted by that server. Choose the entry for the actual product before copying connection settings from another environment.

## Connect and choose a database

Enter the host, port, database, credentials, and required TLS options. These sources use database selection rather than PostgreSQL-style schema switching in the WhoDB sidebar.

A successful connection does not establish that you chose the intended database. Check a familiar table and a few known records before making changes.

Server-configured profiles use `WHODB_MYSQL`, `WHODB_MARIADB`, or their numbered variants. For compatible products such as TiDB, use the corresponding catalog entry when available.

## Explore an object

Use **Tables** to find the object and **Info** to inspect its metadata. Open **Data** for filters, sorting, and the supported row actions.

For a custom query, open Scratchpad. A small MySQL sample might be:

```sql
SELECT id, username, email
FROM users
ORDER BY id
LIMIT 25;
```

Use fields from your actual table. If it exists in a different database, confirm the sidebar selection or qualify the object using syntax accepted by the server.

## Keep dialect differences visible

WhoDB sends queries to the connected source. It does not make SQL from another database engine automatically compatible. When moving a saved query, check its functions, quoted identifiers, types, and any server-specific syntax.

For a failed query, read the source's error and test a smaller statement before changing connection settings. See [MySQL's reference manual](https://dev.mysql.com/doc/refman/8.4/en/) or [MariaDB's documentation](https://mariadb.com/docs/server) for engine behavior.

## Verify writes and exports

Read a record again after editing it. For an export that needs a filter, run a query and export its result rather than relying on the grid's filter to limit a whole-object export.
